# 09：状态、记忆与持久化

[上一章](08-async-context.md) · [目录](README.md) · [下一章](10-information-sources.md)

## 1. 同一个“记忆”词背后的五种东西

| 层次 | 本项目例子 | 存在时间 | 主要用途 |
|---|---|---|---|
| 浏览器内存 | sessions、logs | 当前页面生命周期 | 展示会话与日志 |
| 调用上下文 | ContextVar | 当前执行上下文 | 获取目录与路由编号 |
| 图运行状态 | messages 等 | 执行过程中 | 模型下一步决策 |
| checkpoint | SQLite 数据库 | 文件保留期间 | 保存和恢复会话图状态 |
| 外部知识/业务数据 | RAGFlow、MySQL | 外部服务管理 | 提供事实与资料 |

清空一种，不代表其他四种也清空。调试时先说清楚“哪层丢了”。

## 2. 什么是 checkpoint

Checkpoint 可以理解为执行状态的快照，而不只是把最终回答存一份。它让框架具备继续会话或恢复状态所需的基础。

LangGraph 官方区分 thread 范围的 checkpointer 和跨 thread 的 store：[持久化说明](https://docs.langchain.com/oss/python/langgraph/persistence)。本项目显式配置的是前者，没有看到业务层用户画像 store。

因此，文件名 checkpoints.db 里的“持久”表示写到持久存储，不意味着模型学会了一条永久知识，也不意味着系统实现了跨所有会话的用户记忆。

## 3. thread_id 如何决定状态归属

```python
config = {"configurable": {"thread_id": "lesson-a"}}
```

继续使用同一个 ID，框架有机会关联已有状态；换一个 ID，通常对应另一段会话状态。是否实际给模型保留全部历史，还取决于图状态更新、上下文管理和框架配置。

一个常见测试：第一轮告诉系统一个临时偏好；第二轮使用相同 ID 追问；第三轮换新 ID 再问。不要把第一轮的内容重复写进第二轮问题，否则无法验证历史是否真的参与。

当前页面每次生成新 UUID，做这个实验需要用 API 或先增加“继续当前会话”的前端流程。

## 4. 为什么使用 AsyncSqliteSaver

当前 Agent 使用 astream，服务由 asyncio 管理，所以 saver 也采用异步接口并在同一服务生命周期中初始化。

FastAPI `lifespan` 进入 `agent_lifespan`，后者用异步上下文管理器打开数据库并创建 Agent。这样连接不会在服务启动前就脱离预期生命周期随意使用。FastAPI 生命周期结构可参阅 [官方说明](https://fastapi.tiangolo.com/advanced/events/)。

requirements 当前已显式加入 `aiosqlite==0.22.1` 与 `langgraph-checkpoint-sqlite==3.1.3`。如果仍提示缺包，应先核对实际运行的 Python 环境，而不是继续假设依赖清单里没有它。

## 5. 重启后哪些东西可能恢复

SQLite 文件和 output 文件在磁盘上，正常情况下重启进程不会自动删除它们。当前 WebSocket 连接、后台 Task 对象和浏览器日志不由这个数据库自动恢复。

有 checkpoint 不等于有“失败任务自动重新排队”功能。要自动续跑，还需要明确恢复入口、恢复配置、外部副作用处理以及任务状态管理。

如果工具已经写出文件，但状态保存前进程退出，恢复后可能再次执行同一操作。持久化让恢复成为可能，也让幂等性更重要。

## 6. 并发与会话锁

不同 thread_id 可以有不同状态；但同一个 ID 同时发两个请求时，业务语义可能冲突：两次运行都以旧消息为基础继续，写同名报告，前端结果互相混合。

当前没有看到每会话运行锁或排队策略。后续可选“同会话只运行一个任务”“新输入排队”或“用户明确取消旧任务后开始新任务”。具体选哪种取决于产品需求。

SQLite 支持持久化，但它不是自动分布式调度系统。多进程部署还涉及连接池、锁竞争、共享事件路由和任务注册表。

## 7. 什么应该存，什么不应该盲目存

为了追踪结果，通常希望保存用户输入、最终结果、来源、运行状态和重要错误。但工具结果可能包含客户信息、访问路径或敏感文档，应控制保留范围和访问权限。

不要把 API Key 写进消息或日志。当前教程使用配置变量名，不读取或复制真实 `.env` 内容。

## 8. 离线实验与真实框架的区别

[03_state_and_paths.py](examples/03_state_and_paths.py) 用临时 SQLite 数据库演示“同一 ID 读回历史、不同 ID 分开、关闭连接后重新打开仍可读”。

它使用教学表结构，不读取或解析真实 checkpoints.db，不模拟 LangGraph 的内部 checkpoint 格式。其目的只是帮助理解存储与 ID 关联。
